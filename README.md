# Procedural Alpine Lake

![Reveal shot](docs/img/02_reveal.jpg)

A 60 second cinematic flight through an alpine lake valley, rendered entirely from code.

Nothing in the renderer or the soundtrack is loaded from a file: there are no textures, meshes, HDRIs or audio samples (the images in `docs/` are only for this page). The terrain, erosion, forest, rocks, water, waterfall, sky, camera moves, color grade and the full soundtrack are all generated by the Python and GLSL in this repository: about 13,800 lines of Python and 14,400 lines of GLSL.

The film was rendered at 2752x1152, 24 fps with motion blur and upscaled to 3440x1440 (21:9). It took about 14 hours on a laptop iGPU (AMD Radeon 780M).

## What is generated

- **Terrain.** An analytic height function describes a glacial trough with a lake, side valleys and peaks. It is baked to an 8192 x 8192 map (4 m cells, 32 x 32 km) and run through a GPU erosion simulation written as compute shaders: depression filling, fluvial routing and incision, sediment transport and hillslope relaxation. A 1 m near map adds fine analytic detail around the lake.
- **Hand-placed features.** A twin waterfall over a dark rock step on the east shore and a boulder-choked inflow stream are carved into the eroded terrain. Their placement is derived from the height map, so they survive terrain changes.
- **Forest.** Subalpine conifers (spruce, fir and larch), one tree slot per 4 m cell, with procedural stand structure (gaps, groups, height cohorts, dominant trees) and ray-marched crowns with layered self-shadowing.
- **Ground and rocks.** Grass blades, forbs, wildflowers, shrubs and stones near the camera, granite boulders on the shores, scree and forest floor, packed shore cobbles and cliff materials.
- **Water.** Lake waves with deep and capillary dispersion, wind gust patches, clear glacial-lake optics with reflection, refraction, a visible lake bed, scattering and sun glints. The waterfalls are thin volumetric sheets.
- **Sky and light.** Single-scattering atmosphere (Rayleigh, Mie and ozone), aerial perspective and volumetric cumulus clouds.
- **Camera.** Keyframed spline paths with easing and gentle drone drift. Most ground-level paths search their neighbourhood for a variant that keeps clear of the terrain, the trees and the shot's hand-placed boulders, checked 15 times per second of the shot. Motion blur comes from per-sample camera times.
- **Finishing.** Local tone mapping, filmic curve, chroma shaping, bloom, vignette and grain.
- **Sound.** A nature bed (wind, foliage, lake, stream, waterfall, meadow, birds) and an orchestral score (strings, horns, choir, piano, celesta, harp, timpani, percussion) synthesized with numpy and scipy, mixed to -14 LUFS with a true-peak limiter. Every cut lands on a downbeat.

## How the renderer works

The world is baked once and cached as `.npy` files in `cache_final/`: on the GPU the analytic heights, erosion, relief, feature carving, the 1 m near map, ambient occlusion and the forest map; with numpy and scipy the shore shaping, talus cones, lake and river water levels and a tileable 3D noise volume. The per-cell tree map is baked on the GPU the first time the renderer loads the world.

Frames are ray marched in a split renderer. `engine/shaders/scene.frag` is compiled once per pass:

1. a cone pre-pass that marches one cone per 4 x 4 pixel block through empty space and stores the distance at which that block's primary rays can safely start,
2. a primary trace that writes a G-buffer (hit distance, hit kind, tree or rock cell and surface info) to two float render targets,
3. one shading pass per hit kind (terrain, trees, rocks, water and so on) that discards every other pixel and blends additively.

`engine/glstrip.py` resolves the `#if` blocks and strips unreachable functions for each pass, so every variant compiles small while staying bit-identical. `engine/gpuslot.py` guards the shared-memory iGPU when several render processes run at once (GPU slots plus a memory watchdog). Frames are rendered as tiled multi-sample HDR, graded on a worker thread while the GPU renders the next frame, and encoded with ffmpeg.

## Requirements

- Python 3.11 or newer
- A GPU with OpenGL 4.3
- ffmpeg on `PATH`
- Plenty of RAM. On the AMD driver full-resolution final frames peak at about 17 GB of commit (`tools/render_final.py` raises the watchdog limit to 30 GB), and a render process that cold-compiles all shader passes peaks at about 6 GB. The scene shader is split into those passes because, compiled as a single program, it committed 45 to 50 GB.

Developed and tested on Windows 11 with an AMD Radeon 780M. Other OpenGL 4.3 drivers (Windows or Linux) should work but are untested. macOS only offers OpenGL 4.1 and cannot run it.

```bash
python -m venv .venv
source .venv/Scripts/activate   # Git Bash on Windows (PowerShell: .venv\Scripts\Activate.ps1, Linux: source .venv/bin/activate)
pip install -r requirements.txt
```

## Usage

Run everything from the repository root.

```bash
# 1. bake the world into cache_final/ (one time)
python tools/bake_final.py

# 2. look at it: one still per shot into out/stills, or a 480x270 animatic
python film.py stills
python film.py preview

# 3. soundtrack: nature bed first, then the score and the final mix -> out/audio/soundtrack.wav
python audio/soundtrack.py --shots audio/film_shots.json --out out/audio/nature/bed.wav --stems
python audio/score_c.py

# 4. the full film: 1440 frames at 2752x1152, 6 to 8 samples per pixel, upscaled to 3440x1440
python tools/render_final.py
```

`tools/render_final.py` is resumable: finished frames are skipped, so it can be stopped and restarted at any time. The result is `out/alpine_lake_film.mp4`.

Useful environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `ALPINE_CACHE` | `cache_final` | baked world to bake into and render (`tools/render_final.py` uses its `--cache` option instead) |
| `ALPINE_NO_SLOT` | unset | `1` skips the GPU slot guard, the compile guard and the memory watchdog (single interactive use) |
| `ALPINE_MAX_GPU` | `3` | parallel GPU processes allowed by the guard |
| `ALPINE_MAX_PROC_GB` | `16` (`30` in `render_final.py`) | per-process memory limit of the watchdog |

## Project structure

```
film.py              film renderer: preview, stills, final frames, encode
still.py             render a single named still
engine/
  render.py          GPU renderer: split passes, tiled multi-sample frames, tree cell bake
  gl.py              OpenGL context, shader #include loader, fullscreen passes
  bake.py            world bake: heights, AO, water and forest maps, 3D noise
  erosion.py         GPU erosion driver
  features.py        waterfall and stream placement and carving
  shots_film.py      the film's 9 shots and camera paths
  camera_path.py     spline camera paths with easing and drift
  post.py            tone mapping and color finishing
  glstrip.py         per-pass shader source reduction
  gpuslot.py         GPU slot and memory guard
  shaders/           scene, terrain, trees, rocks, ground, water, falls, sky, bake and erosion shaders
audio/
  soundtrack.py      nature bed and ambience
  score_c.py         the film's score and final mix
  score_a.py, score_b.py, music.py   alternative scores
  film_shots.json    shot timings that drive the music
tools/
  bake_final.py      bake the final world
  render_final.py    resumable final render and encode
docs/
  refs/              the 10 reference photos
  img/               rendered stills from the film
```
